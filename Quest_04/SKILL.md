# Google 자료 동기화·누락 보충 스킬 — 검토용 초안

현재는 동작 설계를 검토하는 단계다. 이 파일을 작성한 것만으로 자동 실행·누락 보충 기능이 설치되거나 구현되지는 않는다. 아직 없는 명령·API를 추측해 호출하지 않는다.

## 반복 작업

Gmail·Google 캘린더를 한국시간 매일 08:00·12:00·18:00·24:00에 조회한다. 24시는 다음 날 00:00이다. 시간이 지나도록 PC나 앱이 꺼져 있었다면 앱 시작 시 마지막 성공 기록과 비교해 즉시 한 번 보충 조회한다.

## AI의 점검·실행 절차

1. 적용 대상 프로젝트의 README·현재 동기화 모듈 문서를 읽고 실제로 지원하는 조회 경로를 확인한다.
2. Gmail과 캘린더 각각의 연결 상태, 자동 조회 설정, 마지막 성공 시각·처리한 시간 구간을 확인한다. 계정·키·토큰을 화면이나 로그에 복사하지 않는다.
3. 현재 한국시간 기준 가장 최근 도래한 조회 시각을 구하고, 마지막 성공 기록으로 그 시각까지 조회했는지 판단한다. 기록이 없으면 초기 조회가 필요함을 구분한다.
4. 지원되는 읽기 조회 경로가 있으면 사용자가 승인한 범위에서 호출한다. 놓친 시각이 여러 개여도 현재 시점까지 자료를 포함하는 보충 조회 한 번으로 합친다. 없는 실행 기능은 구현 필요로 보고한다.
5. 실제 응답을 확인하고 Gmail·캘린더별 성공·실패·중복 제외·검토 대기 건수를 요약한다. 연결 실패를 성공으로 기록하지 않는다.

## 프로그램에 추가할 자동화 규칙 — 구현 예정

- 앱 시작·절전 복귀·인터넷 재연결·정기 확인 때 누락 여부를 판단한다. 노트북이 켜져도 앱이 실행되지 않으면 이 로직은 실행되지 않는다. OS 자동 시작 등록은 별도 범위다.
- 마지막 성공 시각과 처리 구간은 Gmail·캘린더별로 보존한다. 조회 시도 시각만으로 완료 처리하지 않는다.
- 동시 실행 잠금으로 정시 조회·보충 조회·수동 조회가 겹치지 않게 한다. 실행 중 새 요청은 중복 실행 대신 대기 상태로 표시한다.
- Gmail만 실패하면 Gmail만 재시도한다. 실패 시 제한된 재시도와 대기 시간을 적용하고, 권한 오류는 재연결 필요로 표시한다. 구체 재시도 횟수는 구현 시 명시한다.
- 조회 범위는 마지막 성공 이후를 포함하되 API 조회 한도·기존 설정을 지킨다. 최초 조회는 기존 Gmail 최근 7일·캘린더 설정 범위를 사용하며 한도 때문에 누락되는 범위는 표시한다.
- 캘린더는 기존 중복·충돌 정책을 유지한다. Gmail 후보는 일정·할 일·프로젝트로 분류하되 사용자 검토 후 저장한다.
- 메일 발송·스팸 이동·Google 원본 수정·자료 삭제는 이 스킬의 범위가 아니다. 외부 공개 화면은 동기화 실행 권한을 갖지 않는다.

## 결과 표시

요청 원인(정시/시작/절전 복귀/재연결/수동), 조회 대상 구간, Gmail·캘린더 각각의 성공 여부, 마지막 성공 시각, 다음 예정 시각, 검토할 후보와 남은 문제를 표시한다. 실제 실행하지 않은 항목은 “실행 안 함”으로 적는다.
