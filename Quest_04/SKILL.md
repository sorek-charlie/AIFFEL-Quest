# Google 자료 동기화·누락 보충

시간에 맞춘 자동 실행은 PC 앱이 담당한다. 이 스킬은 앱의 자동 보충을 실행·점검하고 결과를 설명한다. 스킬 파일만 설치해 두는 것으로 PC가 켜지거나 예약 실행되는 것은 아니다.

## 적용 대상·준비

Charlie’s Scheduler 소스 프로젝트 루트에서 사용한다. `scripts/google-sync.mjs`와 로컬 `Charlie's Scheduler.exe`가 있는지 확인한다. Node.js24.22.1 이상이 필요하다. 앱에서 Google 계정과 자동 조회를 먼저 설정해야 한다. 설치 위치는 `<프로젝트>/.agents/skills/google-sync-recovery/SKILL.md`다.

## 실행 절차

1. 프로젝트 지침과 README·`apps/api/src/infrastructure/calendar-providers/README.md`를 읽고 대상 프로젝트·조회 범위를 확인한다. 별도 연결된 Gmail/Calendar 도구로 대체하지 않는다. 이 앱에 승인된 계정과 다른 계정이 연결돼 있을 수 있다. 노트북 로그인 후 자동 실행 점검을 요청하면 옆 Quest_04 폴더의 `scripts/google-sync-startup.ps1 -Mode Status`로 사용자 예약 작업도 확인한다. 설치·해제는 그 설정 변경이 요청된 경우에만 수행한다.
2. `node scripts/google-sync.mjs --status`를 실행한다. 공개 상태 필드인 연결 여부·활성화 여부·마지막 성공·누락 시각·재시도 결과를 확인한다. DB·키·토큰·쿠키를 직접 열거나 출력하지 않는다. CLI의 DATA_UNAVAILABLE / DATA_ACCESS_DENIED 또는 EACCES/EPERM은 데이터 부재와 실행 환경 제한을 구분해야 한다. 이미 연결된 PC 앱이 있는데 접근이 막히면, 도구가 지원하는 승인된 로컬 실행 권한으로 같은 CLI를 한 번 재실행한다. 승인 거절 시 중단하고 환경 제한을 보고한다. 계정을 새로 연결하라고 먼저 단정하지 않는다.
3. 사용자가 누락 보충을 요청했다면 `node scripts/google-sync.mjs --recover --wait-seconds 120`를 실행한다. 앱이 꺼져 있으면 CLI가 로컬 실행파일을 시작하고 앱의 자동 조회 결과를 기다린다. 앱이 켜져 있으면 중복 프로세스를 만들지 않는다. CLI 자체는 별도 Google 조회나 인증 우회를 하지 않는다.
4. 대상 시간 구간을 이미 성공적으로 처리했다면 보충을 반복하지 않는다. 방금 수신한 메일을 정시와 관계없이 강제로 확인하려는 요청은 PC 앱의 수동 조회 기능을 안내한다. 이 CLI는 최신 도래 시각의 누락 보충용이다.
5. 종료 코드0과 `completed:true`, 서비스별 `state:ok`, 비어 있는 `outstanding`을 함께 확인한다. 코드2는 미완료/대기, 코드1은 실행 오류다. 시간 초과 뒤에는 `--status`로 확인하고 새 실행 요청을 반복 발행하지 않는다.
6. Gmail 권한 부족·연결 해제·자동 조회 꺼짐은 성공으로 표시하지 않는다. 실제 권한은 앱이 이미 승인된 Gmail 프로필 읽기로 확인할 수 있으나 새 권한을 자동으로 승인하지 않는다. 필요하면 사용자가 PC 앱에서 Google을 다시 연결하도록 안내한다.

## 프로그램의 동작 규칙

- 한국시간 매일08·12·18·24시. 24시는 다음 날00시다. 앱 시작 즉시 검사하고 실행 중15초마다 누락을 재확인한다. Quest_04의 설치 스크립트는 Windows 사용자 로그인과 매일00·08·12·18시 앱 시작을 등록한다. 로그인 전이나 전원이 꺼진 상태에서는 수집할 수 없다. 이미 켜진 앱은 추가로 시작하지 않는다.
- 서비스별 `coveredThrough`와 최근 도래 시각을 비교한다. 여러 시각을 놓쳤어도 현재까지 조회 한 번으로 합친다. 기록 없는 첫 실행도 초기 조회한다.
- Gmail·캘린더 각각 완전 성공해야 lastSuccessAt/coveredThrough를 갱신한다. 부분 응답·페이지 한도·오류를 성공으로 기록하지 않는다.
- 구간당 초기1회+30초 뒤1회+120초 뒤1회, 총3회다. 실패한 서비스만 재시도하고 대기 상태를 보존한다. 다음 정시 구간 또는 재연결 후 다시 검사한다.
- 진행 중 자동 확인은 새 조회를 겹치지 않는다. PC 앱에서 온 수동 요청은 대기시키고 같은 서비스 요청은 하나로 합친다.
- Gmail 초기 최근7일, 장기 누락은 마지막 성공 이후를 포함해 최대366일. 한도 초과는 partial로 표시한다. Gmail은 검토 후보만 생성한다. 캘린더는 변경 커서·기존 중복/충돌 정책을 사용하고 만료 커서는 전체 조회로 한 번 재시도한다.

## 결과 보고

요청 원인, 기준 시간 구간, Gmail·캘린더 각각의 상태·마지막 성공 시각, 이번 조회에서 읽은 메일 수·이번 조회에서 생성한 검토 후보 수·캘린더 반영 수, 다음 예정 시각과 남은 문제를 짧게 보고한다. UTC 기록은 한국시간으로 바꾸고, 실제 읽은 결과가0건이면0건 그대로 적는다. 후보 생성과 일정·할 일·프로젝트 확정 저장을 구분한다.

메일 발송·스팸 이동·Google 원본 수정·삭제·권한 확대·비밀값 공개는 범위 밖이다. 외부 열람 화면에서는 실행할 수 없다. 파일 수정·설정 변경·GitHub 업로드는 별도 요청이 있을 때만 한다.

조회 결과의 pending은 해당 조회가 새로 만든 후보 수다. 전체 검토함의 현재 총건수로 표현하지 않는다.
