# 디자인 시스템

업무 수행 화면(Operate). 밝은 실내에서 자료를 읽고 검토하는 사용자를 위해 밝은 중립 배경과 짙은 잉크를 사용한다.

- 배경 `#eef1f4`, 표면 `#ffffff`, 본문 `#18232e`, 보조 `#526374`, 테두리 `#d7dee5`, 동작 `#245a9a`.
- 한국어 시스템 글꼴, 본문 16px(1800px 이상 17px), 보조 글자 최소 14px. 한국어는 어절 단위 줄바꿈(keep-all). 숫자에 tabular-nums 적용.
- 작업 영역은 최대 폭 제한 없이 화면 전체 폭을 쓰고, 여백은 화면 폭에 비례(16~48px)한다. 미리보기·입력란은 화면 높이에 맞춰 늘어난다.
- 데스크톱은 왼쪽 기능 탐색과 본문 작업영역, 모바일(700px 이하)은 상단 고정 가로 탐색과 단일 열 배치, 저장 버튼은 2열 격자.
- 컨트롤은 눈에 보이는 레이블, 명확한 포커스와 활성 상태를 갖는다. 표가 좁으면 가로 스크롤한다.
- 재무 보고서 선택 순서는 간략보고서 → 심층보고서 → 종합보고서로 유지한다. 기본 선택은 간략보고서다. 간략보고서에는 “참고 양식 반영”, 심층보고서에는 “8장 양식 참조”를 표시한다.
- 첫 화면은 핵심 업무와 정기 일정만 간결하게 보여준다. 재무 분석은 왼쪽에 자료·검토·AI 실행, 오른쪽 상단에 실제 처리 단계의 진행률, 그 아래에 비식별 PDF 양식 또는 생성된 결과의 텍스트를 둔다. 파일 선택 바로 아래에 선택한 모든 첨부 파일과 개수를 표시하고 선택이 바뀌면 갱신한다. 검산 불일치 시 보고서 생성을 막고 완료 시 PDF 저장 대화상자를 표시한다.
- 연결 설정과 효과 검증은 핵심 상태·입력값을 먼저 보여주고 상세 설명은 펼쳐 볼 수 있게 한다. 비식별 양식 미리보기에는 가상임을 표시한다.
- 시안은 가상 데이터와 미구현 상태를 명시한다. 자료 없음과 0을 구분한다.
- 정기 보고서는 설정·검증 영역과 확인된 텔레그램 발송 기록을 나란히 배치한다. 모바일에서는 세로로 쌓는다.
- 문서 작성은 자료·결과 2열(모바일 1열)로 표시하며 선택한 외부 AI와 처리 상태를 구별한다.
- 회의록·문서요약은 파일 선택 바로 아래에 첨부 개수와 파일명을 즉시 표시한다. 다중 파일 입력 후 스캔 원본별 검색 PDF와 통합 요약 PDF의 저장 상태를 보여주고, 선택한 외부 AI 서비스로 원문이 전송됨을 표시한다.

## 메인 랜딩 페이지

사용자가 지정한 별도의 단일 HTML 메인은 검정 배경, 바이올렛·블루 입자, 큰 한국어 제목과 흰 알약 버튼을 사용한다. 다섯 업무는 동일한 수준으로 연결한다. 수시·정기 분석과 개인 텔레그램 보고를 강조하고, 아직 미연결인 봇 명령은 준비 중으로 표시한다. `prefers-reduced-motion`을 지원하며 CDN이 없어도 내용·링크를 사용할 수 있다. 작업 화면은 아래 "다섯 업무 화면 · 파스텔 플레이풀" 규칙을 따르고 탐색 아이콘은 일관된 선형 SVG를 사용한다. 외부 유출 시 법적 책임이 발생할 수 있다는 안내를 작은 글씨로 표시한다.

- 데스크톱 홈은 첫 화면에 제목, 다섯 업무 선택, 개인 텔레그램 일정과 작은 법적 안내를 함께 배치한다. 모바일에서도 업무·텔레그램을 함께 볼 수 있도록 2열의 간결한 선택 영역을 사용한다. 높이가 부족하거나 화면 확대를 사용하는 경우에는 내용을 자르지 않고 세로로 스크롤한다.

- 홈의 업무 설명과 비서 일정은 보라색 배경과 충분히 구별되는 밝은 색으로 표시하고, PC 본문은 15px, 모바일 본문은 13~14px을 기준으로 한다. 작은 화면에서는 가독성을 우선해 필요한 만큼 스크롤을 허용한다.

- PC 홈의 다섯 업무를 한 줄로 배치하고, 나의 비서는 네 가지 소통 항목을 보여주고 그 아래 별도 행에 기존 개인 봇 대화 열기 링크를 표시한다. 모바일은 카드 가독성을 위해 두 열로 배치한다. 텔레그램 대화는 실제 앱에서 확인한다.

- PC 홈은 왼쪽 한 열에 다섯 업무, 오른쪽 한 열에 비서 항목과 비서 봇 확인 내역을 위아래로 배치한다. 봇 내역은 다른 대화방을 가져오지 않으며, 실제 텔레그램에서 확인한 시각을 표시한 정적 내역이다.

- 회의록정리·요약보고서 오른쪽 결과 영역은 데모 박스를 먼저 표시한다. 회의록은 자필 원본·문서화·회의록 정리, 요약보고서는 원본 영상·PDF 요약을 각각 버튼으로 연다. 데모의 식별정보 보호 처리를 명시한다.

- 나의 비서는 네 탭(지시접수·분석결과 보고·Daily News·정부정책, 각 건수 표시)으로 지금까지의 자료를 모두 최신순으로 나열하고, 각 줄에 일시·내용·상태와 "열기 ↗" 링크를 둔다. 맨 위 건에 "최종"을 붙인다. 지시접수는 개인 봇에 보낸 지시, 분석결과 보고는 비서 응답과 수시 업무 결과 발송, Daily News·정부정책은 정기 보고 발송이다. 가상 시연 발송은 노란 "가상 시연" 태그로 구분한다. 선택한 탭은 이 브라우저에만 기억한다.
- 기존 개인 봇 대화창 자리는 "최종 커뮤니케이션(나의 로컬 AI 비서 봇) (YY.MM.DD HH:00 기준)" 목록으로 대체한다. 직전 정시까지 전체 기록을 날짜별·시간 단위 최신순으로 나열한다. 오늘은 모든 시간을, 이전 날짜는 기록이 있는 시간만 보이고, 기록이 없는 시간은 흐린 "소통 없음"으로 표시한다. 각 시간은 마지막 건을 "최종"으로 보이고 나머지는 "이 시간 n건 모두 보기"로 펼친다. 링크는 로컬 기록에 등록된 파일이나 메시지만 연다.
- 홈의 다섯 업무 선택 영역은 데스크톱에서 바닥 가까이 넓히고, 오른쪽에는 허용된 개인 비서 봇의 로컬 대화만 스크롤 가능한 대화창으로 표시한다. 로컬 기록 부분 동기화와 실패 시 마지막 확인 내역을 구분한다. 텔레그램 전체 동기화나 PDF 실시간 수신을 완료한 것처럼 표시하지 않는다.

- 정책·이슈 화면은 간결한 보고 설정과 메시지 예시, 오른쪽의 실행 모니터를 나란히 배치한다. 모니터 위 2/3는 로컬 모델 연결과 실제 작업 단계, 아래 1/3은 해당 보고의 텔레그램 발송 기록을 표시한다. 측정되지 않은 진행률은 만들지 않는다.

## 다섯 업무 화면 · 파스텔 플레이풀 (2026-11-17, 사용자 지정)

재무분석·회의록정리·요약보고서·이슈 브리핑·정부정책 화면에 적용한다. 스타일은 `web/playful.css`, 모션은 `web/motion.js`가 맡으며 `styles.css` 위에 덮어쓴다. 위 첫 줄의 회청색 토큰보다 이 규칙이 우선한다.

- 배경은 흰색, 각 화면 상단 히어로만 아주 옅은 파스텔로 칠한다. 업무별 포인트: 재무 하늘 `#2563b8`, 회의록 분홍 `#c0306c`, 요약 노랑(글자 `#8a5a00`), 이슈 민트 `#137a4f`, 정책 라벤더 `#5b44c9`. `body[data-view]`로 전환한다. 흰 글자를 올리는 포인트색은 4.5:1 이상을 유지한다.
- 제목·패널 제목·큰 숫자는 둥근 굵은 글꼴 Jua(Google Fonts, 실패 시 맑은 고딕). 본문은 시스템 한국어 글꼴, keep-all.
- 패널 24px, 히어로 32px 라운드, 버튼·태그·메뉴는 알약형. 카드 안 영역은 테두리 대신 색면을 쓴다. 텔레그램 말풍선과 페이지 미리보기는 예외로 허용한다.
- 히어로는 왼쪽 제목·설명, 오른쪽 전용 칸에 유광 아이콘과 위젯 3개. 위젯은 흐름 배치로 서로 또는 제목을 가리지 않는다. 1000px 이하에서는 제목 아래 한 줄로 흐른다.
- 위젯 문구는 화면에 이미 있는 사실(형식·일정·지역)만 쓴다. 숫자는 단위보다 크게 쓰고, 카운트업은 정지 상태에서도 최종 숫자가 보인다. 실측되지 않은 수치는 위젯에 넣지 않는다.
- 모션은 GSAP 3.12.5 + ScrollTrigger(jsDelivr). 등장은 스프링, 위젯은 넓은 화면에서만 천천히 떠 있고, 손을 올리면 통통 기울어진다. 시스템의 `prefers-reduced-motion` 설정을 적용한다. CDN이 없어도 위젯과 내용은 정적으로 보인다.
- 재무분석은 히어로를 압축해 넓은 화면에서 한 화면 안에 들어오게 유지한다.

## 오른쪽 상단 · 최종 데모 결과 (2026-11-18, 사용자 지정 · 절대 규칙)

- 다섯 업무 화면의 오른쪽 상단에는 지금까지 만든 데모 중 최종 결과 이미지를 표시한다. 재무분석은 미리보기 칸, 회의록·요약보고서는 결과 칸 맨 위, 이슈·정책은 오른쪽 열 맨 위(그 아래 실행 모니터).
- 우선순위: `데모자료/<업무 폴더>`의 HTML을 `scripts/render_demo_html.py`로 렌더링한 이미지 → 없으면 기존 데모 PDF 페이지 이미지(`previews/pages/demo-*`). 둘 다 없으면 "HTML 아직 없음" 안내를 표시한다.
- 비식별 가상 양식(result-*)은 사용하지 않는다. 기존 파일은 `output/archive/비식별_20261118/`에 보관했다. "비식별 PDF 양식 보기" 링크와 하단 보고서 미리보기 패널은 제거했다.
- 데모 이미지는 git에 포함하지 않는다(`web/previews/pages/demo-*/`).

## 디자인 루프 보완 규칙 (2026-11-18)

- 넓은 화면(1001px 이상)의 업무 히어로는 압축형(제목 34~44px)으로 두어 오른쪽 상단 데모 결과가 첫 화면에 보이게 한다. 1360px 이하에서는 유광 아이콘을 숨겨 위젯이 제목 칸을 침범하지 않게 한다.
- 1000px 이하 한 열 배치에서는 최종 데모 결과를 입력보다 먼저 둔다. 이슈·정책은 851~1200px에서 2열(보고 설정 | 데모+모니터, 아래 텔레그램).
- 데모 결과 이미지는 클릭(또는 Enter)으로 확대 보기, ‹ ›·화살표로 쪽 이동, Esc로 닫는다. 생성 결과 텍스트에는 확대 표시를 붙이지 않는다.
- 오프라인(CDN 없음): Jua 글꼴을 실제로 받았을 때만 사용하고 아니면 시스템 글꼴 800 굵기, GSAP가 없으면 정적으로 표시한다.
- 상단 상태 점은 실제 연결 확인이 아니므로 중립 회색으로 둔다(성공 초록 금지).
- 모바일 가로 메뉴는 오른쪽 끝 흐림으로 넘김을 알리고, 화면 전환 시 선택한 메뉴를 보이게 스크롤한다.
- 입력 안내 글자 #5f6876(4.5:1 이상), 포커스는 업무 포인트색 3px 테두리 + 옅은 후광.

## 입력 간소화 (2026-11-18, 사용자 지정)

- 재무분석 히어로는 제목만 두고 오른쪽에 간략·심층·종합보고서·세무조정계산서 그림 카드 4개를 둔다. 세무조정계산서는 `데모자료/01_4.세무조정계산서`의 PDF를 데모 미리보기로 쓴다.
- 기업명·AI Provider는 레이블과 입력을 한 줄에 둔다. 첨부 파일은 개수와 상관없이 모두 펼쳐 보인다. 추가 입력은 "요청사항 입력" 상자의 요청사항 칸 하나만 둔다.
- 별도 "자료 확인" 단계와 확인란, 전송 안내 문구를 두지 않는다. 작은 "분석 실행"이 원자료 검산을 먼저 하고, 불일치면 생성을 막고 이유를 표시한다.
- 오른쪽 진행률은 실제 단계 값만큼 강아지가 막대 위를 달린다. 진행률 아래 "저장" 하나로 저장 대화상자를 열고, 하단 저장 버튼 줄은 두지 않는다.
- 회의록정리·요약보고서는 실행 시 오른쪽 결과 상단에 현재 작업과 퍼센트를 나란히 표시하고 아래에 강아지 진행 막대를 둔다. 음성 전사 퍼센트는 재생 길이 대비 전사된 구간을 기준으로 표시한다. 회의록정리·요약보고서는 같은 양식: "원본문서화"(추출 + 검색 PDF)와 업무 이름 버튼(회의록정리/요약보고서, AI 분석), 3줄 요청사항 칸과 ▲▼ 높이 조절, 한 줄 AI Provider.
- 정부정책 설명은 "전국 · 서울 · 경기 중소기업 지원사업".
