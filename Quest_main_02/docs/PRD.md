# PRD — 중소기업 AI 업무 작업실

상태: 회의록·문서요약의 다중 파일 추출, 검색 가능 PDF 및 통합 요약 PDF, 업무용 OpenAI·Anthropic API 선택 기능을 구현했다. API 키 미설정으로 실제 유료 모델 호출은 검증하지 않았다. 정기 뉴스·정책은 로컬 LLM을 사용하며 수동 PDF 발송은 확인했고 정기 시각 자동 발송은 미검증이다. 계정과 연도 인식이 가능한 PDF·엑셀·CSV·ZIP에 대해 간략·심층·종합 PDF 생성을 구현했다. 서식과 OCR에 따라 추출 실패가 가능하며 원자료 검토가 필요하다. 2026-11-17.

## 사용자와 목표
중소기업 대표·경영진에게 회사와 재무 현황을 설명하고 반복 업무를 정리한다. 운영자의 직무는 미확정. 수작업 기준 시간은 측정 전이다. 입력 → AI 처리 → 검증 → 사람이 검토 → 결과 전달 흐름을 평가한다.

## 업무별 기능
| 기능 | 입력 | 결과 | 모델·빈도 |
|---|---|---|---|
| 재무분석 | PDF·엑셀·CSV, 필요시 사업계획 | 간략·심층·종합보고서, 검산, 분석 입력 PDF | 유료 LLM 선택, 지표는 코드 계산 |
| 회의록 | 여러 문서·이미지·음성·동영상(음성) | 원본별 검색 PDF, 통합 요약보고서 PDF | 수시, ChatGPT 또는 Claude 선택 |
| 문서요약 | 여러 문서·이미지·음성·동영상(음성) | 원본별 검색 PDF, 통합 요약보고서 PDF | 수시, ChatGPT 또는 Claude 선택 |
| 이슈 브리핑 | 뉴스·출처 | AI·경제·정치·사회·기술·주식 | 매일 09:00, 로컬 기본 |

Telegram 결과 발송은 기존 개인 봇을 사용하며 두 수동 PDF 전송을 확인했다. 별도 명령 수신 코드는 허용 사용자와 채팅을 검사하지만 기존 봇과 동시에 업데이트를 가져오면 충돌하므로 운영 연결하지 않았다. 기존 봇에서 업무 명령을 수행하는 기능은 추가 연결과 실제 검증이 필요하다.

시간대 Asia/Seoul. 뉴스는 Bing News RSS 제목과 원문 링크를 사용하며, 본문은 읽지 않는다. 꺼진 PC는 로그인 후 놓친 당일 작업을 실행하되 정기 자동 발송 자체는 아직 시각 도래 후 확인이 필요하다. 일부 출처 실패와 텔레그램 결과 불명확은 상태에 기록한다.

## 재무 흐름
자료 업로드 → 회사·기간·단위 검토 → 보고서 유형 선택 → PDF 추출/OCR·계정 정규화 → 소계 및 자산=부채+자본 검산 → 코드 계산 → 출처와 함께 결과 검토 → 보고서 생성·전달. 대조값이 없으면 미검증, 불일치하면 오류와 원문 위치를 표시한다. 단위·기간·실적/가정은 구분하며 LLM에는 확인된 데이터만 전송하도록 설계한다. 공급자·외부 전송 범위는 별도 결정.

- **간략보고서:** [참조 분석](간략보고서_분석.md)의 7쪽 구성. 현재 7쪽 PDF를 생성한다.
- **심층보고서:** 제공받은 8쪽 PPTX의 구성을 참고한다. [심층분석 양식 분석](심층분석_양식.md) 참조. 인식 가능한 재무자료를 정규화하고 8쪽 PDF와 원자료 대조를 생성한다.
- **종합보고서:** 제공된 종합보고서 참고 HTML의 표지·목차, 회사 개요·성장 실적·성장 계획·자금 활용 순서와 페이지 구성을 따른다. 표·지표는 입력 자료로 채우며 확인에 필요한 자료가 없으면 해당 페이지에 표시한다.

## 간략보고서 계산 규칙 가설
참조 PDF는 이미지이므로 엑셀 수식 검증은 불가능하다. 다음은 표로부터 추정한 규칙이며 원본 확인 전 확정하지 않는다.

| 항목 | 추정 계산 또는 확인 사항 |
|---|---|
| 증감액·증가율 | 당기−전기, (당기−전기)/전기×100. 분모 0·음수 및 부호 전환 규칙 확인 필요 |
| 매출비 | 항목/기준 매출×100. 제품매출과 총매출의 분모 구분 확인 필요 |
| 부채비율·자본대비 자산 | 각각 부채총계/자본총계, 자산총계/자본총계×100 |
| 매출 영향 | (당기 매출−전기 매출)×전기 이익률로 표 수치에 대체로 부합 |
| 효율 영향 | 당기 매출×(당기 이익률−전기 이익률)로 표 수치에 대체로 부합. 세부 분해·반올림 검증 필요 |
| 매출채권·재고 회전일 | 평균/기말 잔액과 매출/매출원가 분모 확인 필요 |
| 주식 평가 | PDF에 순손익·순자산 비중만 표시. 실제 평가 기준 및 수식 확인 필요 |
| 신용공여 | 중복 소계를 제외하고 금융기관·과목·만기별 합산. 대사 규칙 확인 필요 |

## 화면 및 텔레그램
다섯 업무, 효과 검증과 설정. 재무 화면은 간략·심층·종합 순서, 좌측 입력·우측 진행률과 실제 생성한 PDF 텍스트 미리보기를 제공한다. 생성 전 가상 비식별 PDF 양식, 생성 후 보고서 텍스트를 표시한다. 완료 시 저장 대화상자를 표시하고 PC 저장·Telegram 발송 결과를 구분한다.

정기 보고의 상세 수집, 원문 검증, 메시지와 운영 설계는 [정기 브리핑 명세](정기_브리핑.md)를 따른다. 정규화된 JSON의 메시지 생성과 수동 Telegram 발송 명령은 구현했으나 실제 Telegram 연결은 검증하지 않았다. 이 구성요소는 수집·AI 추론·원문 대조 기능이 아니며 입력의 대조 상태를 검증하지 않는다.

Telegram Bot API를 통한 인증된 사용자·채팅의 입력, 작업 상태 알림과 결과 메시지/파일 전송을 설계한다. long polling 또는 webhook, 파일 제한, 재시도와 장애 정책은 구현 시 공식 문서를 확인해 결정한다. update_id 중복 처리, 비밀키 환경변수 보관, 전송 결과 불명 시 중복 방지 및 수동 확인이 필요하다. 텔레그램과 유료 모델은 외부 통신이다.

## 검증
동일 원자료와 독립 계산을 대조해 대상 수치 100% 일치를 목표로 한다(단위·반올림 규칙 합의 후). 결과 문장은 기업·기간·단위·방향도 확인한다. 장수·빈 페이지·글자 넘침과 누락 표시를 검토한다. 수작업 기준선을 먼저 측정하고 작성+검토+수정 시간을 비교한다. OCR 오류, 누락 및 실패 사례를 기록한다.

## 미결정
간략 엑셀 원본, 심층 양식에 쓰인 원본 엑셀 및 지표별 세부 산식, 작성자 소개 포함 여부, 출처·휴일·장애 처리, LLM 공급자와 외부 전송 범위, 성장계획 자료가 없을 때 처리, 평가 데이터와 기준선.

## 홈 대화와 정기 보고 모니터

홈은 지정된 개인 봇의 로컬 기록만 읽어 대화창에 표시한다. 기존 봇과 충돌하는 추가 Telegram 폴링은 하지 않으며, 텔레그램 전체 기록이나 별도 발송 PDF는 자동 동기화되지 않는다. 연결 실패 시 같은 브라우저 탭에 보관된 마지막 조회를 표시한다.

뉴스·정책 화면 오른쪽에 로컬 모델 연결, 기록된 작업 단계와 해당 보고의 Telegram 발송 상태를 표시한다. 진행률은 단계 기준이며 과거 기록에서 추정하지 않는다. 실제 예약 시각과 실시간 텔레그램 전체 동기화는 아직 검증하거나 구현하지 않았다. 데모 원본의 식별정보 노출 구간과 PDF 화면 캡처는 가린다.
