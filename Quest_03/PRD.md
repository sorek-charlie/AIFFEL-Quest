# PRD · ORBIT Todo

과제 D-4 | 작성일 2026-11-01 | 마감 2026-11-05 23:59 (한국 시간)

## 1. 목표와 사용자
개인 사용자가 할 일을 추가·조회·수정·완료·삭제하고, 앱을 껐다 켜도 데이터가 남는 Todo 앱을 만든다. 길 A(SQLite)를 검증한 뒤 길 B(Supabase)로 저장 대상을 전환한다.

## 2. 필수 기능과 수용 조건
- Todo CRUD: 1~160자 제목, 완료 체크, 수정·삭제를 지원한다. 오류는 화면에 표시한다.
- 길 A: 로컬 SQLite에 저장한다. 앱 재시작 후 제목·완료 상태를 유지하고 삭제한 항목은 복원되지 않는다.
- 길 B: Supabase Auth 로그인 후 사용자 JWT로 저장한다. 재로그인·앱 재시작 후 동일 데이터를 조회한다.
- 저장소 전환: 현재 저장소를 명시하고 사용자가 A/B를 선택한다. 두 저장소의 데이터는 독립적이며 자동 이관하지 않는다.
- RLS: 익명 접근과 사용자 B의 A 데이터 조회·수정·삭제·소유자 위조를 차단한다.

## 3. 데이터와 구조
Todo는 id, 소유자, 제목, 완료 상태, 버전, 생성 시각을 가진다. 브라우저 → 인증된 Node API → SQLite 또는 Supabase REST 구조다. 저장소 선택은 bootstrap에서 수행한다. 버전 검사로 오래된 수정·삭제를 거부한다.

## 4. 보안과 품질
Supabase의 SELECT/INSERT/UPDATE/DELETE 정책은 auth.uid()와 owner_id를 비교한다. service_role/secret 키는 일반 CRUD에 사용할 수 없다. 키는 Git 제외 로컬 DB에 암호화 저장하고 토큰·비밀번호를 브라우저 저장소나 로그에 남기지 않는다. 모바일 360px와 키보드 조작을 지원한다.

## 5. 검증과 제출
작동 화면 또는 3분 시연 + 이 PRD 한 장을 GitHub/Drive 링크로 제출한다. 각 저장소에서 추가·수정·완료·삭제 → 앱 종료·재실행 → 보존 확인을 기록한다. 클라우드 전환 결과와 두 사용자 RLS 검사 결과를 한 줄씩 남긴다. 외부 배포 URL은 선택 제출한다.

## 6. 현재 상태와 범위
로컬 CRUD·완료·삭제·재시작 보존 및 전체 자동 테스트 22개 통과. Supabase 테스트 프로젝트를 생성하고 migration 적용·사용자 JWT CRUD·앱 프로세스 재시작 후 완료/삭제 상태 보존을 실제 확인했다. 익명/A/B 교차 접근·소유자 위조 RLS 검사 7개 항목을 통과했다. 예약·Gmail·3D는 추가 기능이며 과제의 Supabase 검증을 대체하지 않는다.
