# PRD · ORBIT Scheduler

**목표**: 내 일정·할 일을 지속 저장하고, 공유 URL로 들어온 고객의 약속 신청을 내가 승인한 뒤 확정한다.
**사용자**: 소유자 1인 관점으로 시작하되 모든 데이터에 owner_id를 두어 계정을 분리한다. 고객은 가입 없이 신청한다.

| 영역 | 필수 기능 | 완료 조건 |
|---|---|---|
| Todo | 생성·조회·수정·완료·삭제 | 화면 새로고침과 앱 재시작 뒤에도 유지 |
| 개인 일정 | 일정 생성·수정·취소, 2D·3D 전환 | 두 보기의 데이터와 선택 결과 일치 |
| 공개 시간 | 요일·휴무·길이·준비시간·시간대 | 기존 점유와 규칙을 반영한 슬롯만 표시 |
| 고객 예약 | 모바일 URL → 날짜·시간 → 신청 | ‘승인 대기’를 명확히 안내 |
| 승인 | 승인·거절·취소, 동일 시간 경쟁 방어 | 승인 시 재검사, 충돌 없는 1건만 확정 |
| 보안 | 소유권·RLS·비밀값 분리 | 사용자 A가 B의 데이터 조회·변경 불가 |

**데이터**: 소유자, Todo, 일정, 공개 프로필, 미팅 유형, 주간 규칙, 날짜 예외, 예약 요청, 감사 기록, 멱등성 기록. UTC 시각과 IANA 시간대를 구분한다. Task 완료와 시간 점유는 별개다.

**구조**: 브라우저 → Node.js 백엔드 → SQLite(길 A) / Supabase(길 B). 프런트는 DB에 직접 접근하지 않는다. 개인용 3D 코드는 고객 경로에 포함하지 않는다.

**규칙**: pending은 확정 점유가 아니다. 승인·일정 생성/이동은 같은 동시성 규칙으로 검사한다. 동일 요청 재전송으로 중복 확정하지 않는다. 고객에게 개인 일정 제목·메모를 노출하지 않는다.

**범위**: 첫 구현은 로컬 Todo와 2D 일정부터. 이후 클라우드·예약 승인·3D 순서. 네이티브 앱, 결제, 팀 라운드로빈, 외부 캘린더 양방향 동기화는 후속 범위다.
