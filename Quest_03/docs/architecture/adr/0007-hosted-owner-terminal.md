# 외부 관리자 터미널과 고객 신청 중계

Sites Worker와 D1에 HTTPS 백엔드를 배포한다. 고객은 `/booking`, 소유자는 `/owner`를 사용한다. 두 경로의 데이터 공개 범위는 다르다.

일정 원본과 비밀번호 해시는 기존 PC SQLite에 둔다. PC가 outbound HTTPS로 관리자 요청을 가져와 기존 application/auth API에 전달한다. 포트 개방이나 로컬 실행 키 공개는 하지 않는다. 관리자 로그인은 기존 비밀번호를 검증하고, 클라우드 응답 쿠키에는 HttpOnly/Strict/Secure를 적용한다. PC 세션이 만료·재시작되면 다시 로그인한다. 원격 초기 설정과 Google 최초 OAuth 연결은 지원하지 않는다.

D1 관리자 대기열은 AES-GCM 암호문만 저장한다. 무작위 IV, 요청 ID/방향을 AAD로 묶고 서버 전용 기존 연결 키에서 키를 유도한다. 비밀번호와 쿠키는 D1 평문으로 저장하지 않는다. HTTPS 서버와 PC 프로세스는 처리 중 평문을 사용하므로 종단간 무지식 구조는 아니다. 클라우드 Secret과 PC 암호화 설정은 배포 파일/Git에 포함하지 않는다.

요청은 queued → running → done이다. 원자 UPDATE RETURNING으로 한 중계만 가져간다. 처리 중 네트워크가 끊기면 변경 성공 여부가 불명확할 수 있어 자동 재실행하지 않는다. UI는 새로고침 후 결과 확인을 안내한다. 25초 요청 만료, 완료 응답 즉시 삭제, 만료 후 1분 정리, 15초 heartbeat 제한을 적용한다. 원본 충돌/승인 경계는 그대로 SQLite 트랜잭션이다. PC와 D1 사이에 분산 트랜잭션은 없다.

고객용 D1에는 허용된 공개 시간과 고객이 직접 제출한 신청만 저장한다. 개인 일정 제목/메모/프로젝트를 공개 projection에 넣지 않는다. PC 공개 시간은 30초 주기, 2분 이상 오래되면 신규 신청을 중단한다. 승인 결과는 버전 단조 증가로 반영한다. 고객 pending은 확정 점유가 아니다.

한 PC 연결을 전제로 한다. 동시 PC 중계는 세션을 서로 공유하지 않으므로 정상 운영 시 앱 한 개를 실행한다. 완전한 클라우드 원본 저장과 PC 없이 운영하는 기능은 별도 마이그레이션 작업이다.
