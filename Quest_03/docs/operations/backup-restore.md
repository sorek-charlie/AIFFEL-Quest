# 백업·복구 절차

SQLite는 쓰기 중인 파일 하나만 무작정 복사하지 않습니다. SQLite backup API 등 일관된 사본 생성 방법을 구현 시 선택합니다.
백업에는 DB schema 버전, 생성 시각, 데이터 건수·checksum을 기록합니다. 세션 비밀값은 DB 백업과 다른 접근 정책으로 관리합니다.
Supabase는 실제 요금제의 자동 백업·복구 가능 범위를 확인하고 부족하면 별도 암호화 export와 보관 정책을 둡니다.

복원 리허설: 격리 DB 생성 → schema/데이터 복원 → 행 수·참조·권한 확인 → Todo 재시작 확인 → 결과 기록.
원본 포함 3사본·2종 매체·1개 다른 장소 원칙을 목표로 하되, runtime/backups 폴더 하나만으로 충족했다고 하지 않습니다.
운영 백업·접속 문자열은 코드 ZIP과 과제 제출물에 넣지 않습니다.
