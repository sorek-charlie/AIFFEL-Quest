# SQLite → Supabase 전환

## 환경 교체

`DATABASE_PROVIDER=sqlite|supabase`로 bootstrap에서 어댑터를 한 개 선택합니다. SQLite 파일을 Supabase에 그대로 올리는 방식이 아닙니다.
자료형·boolean·시간·제약·인덱스·자동 ID·SQL 함수가 다르므로 두 migration 세트를 따로 적용합니다.

## 데이터 이동 절차

1. 로컬 DB의 일관된 백업을 만들고 쓰기를 잠시 중단합니다.
2. cloud 테스트 프로젝트에 schema·RLS·함수를 적용합니다.
3. Supabase Auth 계정을 만들고 로컬 owner ID → cloud auth ID 매핑을 기록합니다.
4. FK 순서에 맞춰 공개 프로필/유형/규칙/할 일/일정/요청을 변환·가져옵니다. 인증 세션·비밀번호·capability는 그대로 복사하지 않습니다.
5. 개수·참조 무결성·시간값·완료 상태를 비교하고 두 사용자 권한·동시 승인 계약 테스트를 실행합니다.
6. 환경변수를 바꾸고 재시작해 지속 저장을 확인합니다. 전환 기록에 결과와 복구 방법을 남깁니다.

샘플 과제라면 데이터를 새로 시작할 수도 있으나, 이 경우 ‘기존 데이터 이관’이라고 기록하지 않습니다.
실패 시 cloud 쓰기를 막고 검증된 로컬 사본과 이전 설정으로 되돌립니다. 이중 쓰기로 맞추지 않습니다.
