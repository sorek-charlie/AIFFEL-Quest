# Quest_01 — 자기 도메인 업무 분해: 법인세 경정청구 검토

내가 일하는 도메인(법인 세무)의 반복 업무 하나를 골라, AI에게 자동화를 맡길 수 있도록 **분해 → 패턴 → 추상화 → 알고리즘** 순서로 정리한 과제입니다.

## 문서 구성

### 1. 도메인 맥락
- 도메인: 법인 세무(법인세 경정청구), 1년 차
- 자동화 대상: 지난 5개 사업연도 법인세 신고 내역에서 **누락되었거나 적게 적용된 세액공제·감면**을 찾아, 경정청구 가능 여부와 예상 환급세액을 정리하는 검토 작업

### 2. 네 동작 분석
- **분해**: 자료 수집 → 사업연도별 구조화 → 공제·감면 요건 대조 → 누락 식별 → 세액 재계산(중복배제·최저한세·이월공제) → 청구 기한 확인 → 증빙 체크리스트까지 7단계
- **패턴**: "요건은 충족했는데 신고에 반영되지 않았거나 계산 기준을 잘못 적용한" 경우가 반복됨
  (예: 상시근로자 수 계산 오류, 사회보험료 세액공제 미신청, 연구인력개발비 누락, 최저한세 이월공제 누락)
- **추상화**: 모든 항목을 `사업연도 · 공제감면 항목 · 요건 충족 여부 · 신고 반영액 · 적용 가능액 · 중복배제/최저한세 영향 · 필요 증빙` 7개 필드 레코드로 표현하고, 연도별 세법 요건은 별도 규정 테이블로 분리
- **알고리즘**: 레코드 변환 → 요건 판정 → `신고 반영액 ≠ 적용 가능액` 항목 추출 → 유리한 공제 조합 선택 → 최저한세 반영 → 기한 경과 연도 제외 → 애매한 항목은 '사람 검토 필요' 표시 → 보고서 출력

### 3. 출력 요구
한국어 마크다운 보고서로 다음 세 부분을 출력합니다.
- 사업연도별 검토 결과 표(반영액·적용 가능액·예상 환급세액·이월공제액·증빙·근거 조문·확신도)
- 결론 요약 3줄
- '사람 검토 필요' 항목과 그 이유

### 4. 검증 기준
경정청구를 담당하는 세무사(또는 팀 선임)가 "누락 판정, 근거 조문, 세액 계산이 맞고 그대로 경정청구서와 고객 보고 자료로 쓸 수 있다"고 평가하는 것이 기준입니다.
요건 해석이 애매한 항목의 최종 판단, 청구 여부 결정, 고객 설명은 사람이 맡습니다.
