# 자기 도메인 업무 분해 — 법인세 경정청구 검토

## [도메인 맥락]
나는 **법인 세무(법인세 경정청구)** 도메인 **1년 차**이고,
**지난 5개 사업연도의 법인세 신고 내역에서 누락되었거나 적게 적용된 세액공제·감면을 찾아 경정청구 가능 여부와 예상 환급세액을 정리하는 검토 작업**을 자동화하고 싶습니다.

## [네 동작 분석]
1. **분해**
   ① 입력 자료 수집(법인세 과세표준 및 세액조정계산서, 공제감면세액 계산서, 재무제표, 원천세·4대보험 자료로 확인한 인원 현황, 투자·연구개발비 내역)
   → ② 사업연도별 신고 내역 구조화
   → ③ 공제·감면 항목별 적용 요건 대조(고용 관련 세액공제, 사회보험료 세액공제, 연구인력개발비 세액공제, 투자세액공제, 중소기업 특별세액감면, 창업중소기업 감면 등)
   → ④ 누락·과소 적용 항목 식별 → ⑤ 중복적용 배제·최저한세·이월공제를 반영해 세액 재계산
   → ⑥ 청구 기한(법정신고기한 경과 후 5년) 확인 → ⑦ 필요 증빙 체크리스트 작성

2. **패턴**
   누락은 대부분 **"요건은 충족했는데 신고서에 반영되지 않았거나, 계산 기준을 잘못 적용한"** 같은 구조로 반복된다.
   - 상시근로자 수 계산 오류(제외 대상, 월별 평균 산정)로 인한 고용 관련 공제 과소 적용
   - 사회보험료 세액공제 미신청
   - 연구인력개발비 중 인건비 등 공제 대상 비용 누락
   - 중복적용 배제 규정 때문에 하나를 고를 때 유리한 조합을 놓친 경우
   - 최저한세로 공제받지 못한 금액의 이월공제 누락

3. **추상화**
   회사별 업종·양식 차이는 버리고, 모든 항목을
   `사업연도 · 공제감면 항목 · 요건 충족 여부 · 신고 반영액 · 적용 가능액 · 중복배제/최저한세 영향 · 필요 증빙` **7개 필드 레코드**로 표현한다.
   연도마다 바뀌는 세법 요건·공제율·한도는 **사업연도별 규정 테이블**로 분리해 로직과 섞지 않는다.

4. **알고리즘**
   1) 자료 로드 → 2) 사업연도별 7필드 레코드로 변환 → 3) 해당 연도 규정 테이블로 요건 판정
   → 4) `신고 반영액 ≠ 적용 가능액`인 항목만 추출
   → 5) 중복적용 배제 대상 조합별로 세액을 계산해 가장 유리한 조합 선택
   → 6) 최저한세 적용 후 환급세액과 이월공제액 산출
   → 7) 청구 기한이 지난 사업연도 제외
   → 8) 요건 해석이 애매한 항목은 **'사람 검토 필요'** 플래그 → 9) 보고서 출력

## [출력 요구]
아래 세 부분으로 된 **마크다운 보고서** 형식으로, **한국어로**.
- 사업연도별 검토 결과 표: 공제감면 항목 / 현재 반영액 / 적용 가능액 / 예상 환급세액 / 이월공제액 / 필요 증빙 / 근거 규정 / 확신도(상·중·하)
- 결론 요약 3줄: 청구 대상 사업연도, 총 예상 환급세액, 우선 처리할 항목
- '사람 검토 필요' 항목 목록과 그 이유

금액은 원 단위로 적고, 항목마다 근거 규정(법인세법·조세특례제한법 조문)을 함께 적는다.

## [검증 기준]
**법인 경정청구를 담당하는 세무사(또는 팀 선임)**가 보고서를 검토하고 다음과 같이 평가할 것.
**"누락 항목 판정과 근거 조문, 중복배제·최저한세를 반영한 세액 계산이 맞고, 이 표를 그대로 경정청구서 작성과 고객 보고 자료로 쓸 수 있다."**
- 보조 기준: 과거에 직접 처리한 경정청구 건에 돌려 봤을 때, 실제로 찾아낸 누락 항목을 빠뜨리지 않고 환급세액 차이가 작을 것

> 사람의 자리: 요건 해석이 애매한 항목(상시근로자 범위, 연구개발 활동 해당 여부 등)의 최종 판단, 세무조사 위험을 고려한 청구 여부 결정, 고객 설명은 사람이 한다.
