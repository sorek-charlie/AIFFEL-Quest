## Cloudflare 배포 주소 처리

GitHub 저장소 URL은 소스 제출용, Cloudflare 서비스 URL은 실행 결과 제출용으로 각각 사용하면 된다. GitHub Pages를 추가로 만들 필요는 없다. 이번 제출용으로 Cloudflare Pages 프로젝트 `tax-return-review-quest`를 별도 생성했다. 실행 주소는 https://tax-return-review-quest.pages.dev/ 이다. 과거의 다른 서비스는 변경하지 않았다.

1. Cloudflare 대시보드의 Workers & Pages에서 기존 프로젝트를 찾는다. `pages.dev` 주소, 커스텀 도메인, 배포 방식과 연결 저장소를 확인한다. `workers.dev`이면 Pages와 다른 구성일 수 있으므로 프로젝트 유형을 먼저 확인한다.
2. 같은 앱의 기존 프로젝트라면 현재 공개용 버전으로 업데이트하고 기존 주소를 유지하는 것을 우선한다. 다른 서비스라면 별도 제출용 프로젝트를 만든다.
3. 이번 프로젝트는 Direct Upload 방식이다. 업데이트는 `python dev/scripts/build_web_deploy.py`가 만드는 전용 폴더를 대상으로 한다. 앱이 `../docs/`를 참조하므로 루트 `index.html`·`app/`·공개 도움말 `docs/` 구조를 유지한다. `app`만 올리면 도움말 링크가 깨진다. EXE·DLL·비공개 백업·실제 원자료·개발 소스는 배포하지 않는다.
4. 새로 만든 배포 폴더를 `npx wrangler pages deploy 폴더경로 --project-name tax-return-review-quest --branch main --commit-dirty=true`로 배포한다. 동일한 앱 파일이면 빌드 도구가 기존 폴더 경로를 안내하므로 내용을 확인해 재사용한다. Cloudflare는 Direct Upload 프로젝트를 Git 통합 프로젝트로 전환할 수 없으므로, Git 자동배포가 필요하면 새 프로젝트를 만든다.
5. 배포가 끝나면 실제 HTTPS 주소를 시크릿 창에서 열어 빈 화면, 가상 샘플 업로드, 보고서 HTML 저장과 Reset을 다시 확인한다. 최종 제출 주소는 일회성 미리보기 주소보다 프로덕션 주소를 사용한다.
6. 확인된 실제 URL을 `docs/submission/README.md`에 기록하고 제출 폼의 ‘배포 결과 URL’에 입력한다.

현재 배포에는 샘플과 제출 문서가 포함되지 않는다. 시연 파일은 로컬 또는 향후 GitHub의 `outputs/main-quest/synthetic-tax-summary.xlsx`와 `samples/synthetic-note.txt`에서 가져와 선택한다. Windows EXE의 공동인증서·기관 수집 연결은 웹 배포에서 제공되지 않는다.
