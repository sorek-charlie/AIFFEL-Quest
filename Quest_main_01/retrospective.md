# 회고 · 경정청구 자료 검토 도우미

작성 기준: 2026-11-04. 아래는 실제 요청·구현·검증 내용을 바탕으로 작성한 제출용 초안이다. 개인의 소감은 마지막 문항을 작성자가 확인한 뒤 제출한다.

## 만들려던 것과 이번에 완성한 것

처음에는 경정청구 자료 수집부터 계산·보고서까지 연결하려 했다. 작업 중 세무사 업무로 범위를 좁히고 노무사 관련 신청 기능을 제외했다. 이번 제출에서는 자료 업로드, 기관·서류·연도 분류, 검토 결과 확인, 보고서 생성으로 이어지는 흐름에 집중했다. 기타 자료도 이름과 부서·연도를 적어 한 파일씩 첨부할 수 있게 했다. 후속 요청으로 ID/PW 로그인, 회원가입, 2~3분 후 가입 안내와 가입10초 후 자동 로그인도 추가했다.

## 어려웠던 점과 해결 과정

같은 원자료로 만든 전문가 결과와 앱 결과가 달랐다. 이를 통해 화면이 완성되고 테스트가 통과해도 세법상 계산이 정확하다는 뜻은 아니라는 점을 확인했다. 공제 최적화와 기신고 공제 대체 등의 한계를 문서화하고, 확정 환급 서비스라는 표현 대신 검토 보조 도구로 범위를 정했다. 해당 금액의 정답을 이번 제출에서 확정한 것은 아니다.

또한 공개 저장소에 실제 회사자료가 섞일 위험이 있었다. 원자료를 저장소 밖에 백업한 뒤 공개 소스에서 분리하고 Git 이력을 정리했다. 기본 회사 데이터를 제거하고 빈 상태에서 시작하도록 바꿨으며, 공개 파일·이력 점검 도구와 독립적인 가상 샘플을 마련했다. 실제 자료를 단순히 이름만 바꾼 샘플은 사용하지 않았다. 회원기능을 추가할 때에는 계정 인증정보와 회사자료를 분리하고, 자료 Reset과 로그인 세션 종료를 구분했다.

사용자가 자료를 한꺼번에 올리는 방식만으로는 어떤 서류를 어디에 넣어야 하는지 알기 어려웠다. 기관·서류·연도별 18칸을 제공하고, 인식되지 않는 기타 첨부는 자동계산에 반영하지 않는다고 표시했다. 첨부 성공과 요건 충족을 구분하는 것이 중요했다.

## AI 협업에서 배운 점

‘업로드를 개선해 줘’보다 ‘기관·서류명·연도별로 한 파일씩 넣고, 기타는 이름을 적어 첨부하게 해 줘’처럼 행동과 예외를 지정한 요청이 구현·검증으로 연결하기 쉬웠다. AI는 화면 수정과 테스트 작성에 도움이 됐지만, 개인정보 삭제 범위와 세무적 결론은 결과물을 따로 확인해야 했다. AI 답변을 근거 없이 최종 판단으로 쓰지 않는 것이 핵심이었다.

## 남은 일과 다음 시도

Cloudflare 배포 주소를 생성하고 실제 HTTPS 환경에서도 가상 샘플과 보고서 저장을 검증했다. 개인정보 점검 후 공개 GitHub 저장소도 만들었다. 3분 이내 영상은 아직 제작해야 한다. 다음 개발은 전문가가 검토한 가상 기준 사례로 공제 조합·농특세·이월·추징을 대조하고, 부족자료 목록에 ‘왜 필요한가’를 연결하는 것이다. 범위를 넓히기보다 한 사례의 입력부터 근거까지 재현 가능하게 만드는 것을 우선한다.
