3. 구현과 데이터 처리

프런트엔드는 HTML·CSS·JavaScript다. 브라우저에서 선택한 원자료를 분석하고 결과를 생성한다. Cloudflare Pages가 웹을 제공하고 Pages Functions와 D1이 회원 인증을 처리한다. 비밀번호는 솔트와 PBKDF2 해시로 저장하고 세션은 Secure·HttpOnly 쿠키를 사용한다. 브라우저 저장소에 비밀번호를 기록하지 않는다. 가입 후 자동 로그인에 필요한 값은 해당 화면 메모리에서만 잠시 사용한다.

계정 DB는 회사 신고서·근로자 자료·생성 보고서를 저장하지 않는다. 실제 회사자료는 저장소 외부에 분리했고, 공개 소스·이력 점검 도구를 사용한다. Windows EXE의 기관 수집 연결은 웹 로그인·업로드와 별개이며 웹에서 공동인증서 수집이 완료됐다고 주장하지 않는다.

4. 가상 샘플과 검증

실제 고객자료에서 가져오지 않은 5개년 요약 XLSX와 기타 설명 TXT를 제공한다. 사업자 식별값은 유효 번호가 아닌 0000000000이며 이름·주민번호·계좌는 없다. 근로자·보험료 증빙은 의도적으로 생략했다.

샘플은 자료 입력·메타데이터·보고서 흐름을 시연한다. 샘플에서 표시되는 0원은 실제 환급 불가 판정이 아니다. 로그인·가입 타이머는 dev/tests/auth_qa.py, 기존 흐름은 dev/tests/submission_demo_qa.py 등으로 확인하며 실제 검증 결과와 미완료 범위를 기록한다.

5. AI 협업·배운 점·한계

사용자는 세무사 업무로 범위를 정하고, 자료 입력 방식과 표·보고서 표현, 개인정보 공개 제외 기준을 구체화했다. AI는 UI·계산 흐름·파일 파서·테스트·배포·제출 문서 초안을 지원했다. 전문가 결과와 앱 결과의 차이는 계산 검증의 중요성을 드러냈다. UI와 테스트 완료를 세무적 정확성으로 확대 해석하지 않는다.

공제 조합 최적화, 기신고 공제 대체, 농특세·이월·추징의 전체 정합성은 전문가 기준 사례로 추가 검증해야 한다. 노무사 업무·고용지원금 신청·국세청 자동 청구·스캔 PDF OCR은 이번 범위에 포함하지 않는다. 계정의 비밀번호 재설정·이메일 인증·관리자 기능도 이번 구현 범위 밖이다.

서비스와 해결할 문제

세무 담당자가 회사의 경정청구 자료를 기관·서류·연도별로 정리하고, 확보한 자료의 검토 결과와 추가 확인사항을 보고서로 확인하는 웹 서비스다. 여러 해의 신고서와 증빙이 섞이면 누락·중복·귀속연도와 계산 근거를 확인하는 데 시간이 든다. 사용자는 회사 회계 담당자와 세무사이며, 최종 세액 판단은 전문가가 한다.

핵심 사용자 흐름

  1. ID/PW로 로그인한다. 회원가입 버튼과 방문120~180초 후 가입 안내를 제공하고, 가입 완료10초 후 자동 로그인한다. 빈 자료 화면에서 ZIP 또는 기관·서류·연도별18칸과 기타 첨부로 파일을 선택한다.
  2. 법인 Q&A와 검토 현황에서 확인할 요건·자료를 살핀다. 자동 인식하지 않는 파일은 참고자료로 구분한다.
  3. 연도별·항목별 잠정 결과를 검토하고, 현재 세션의 보고서 1~4를 HTML 저장 또는 인쇄한다.

최소 성공 기준과 현재 상태

기준 확인 방법 현재 상태
자료를 올리면 기관·서류·연도와 처리 상태를 확인한다 가상 5개년 XLSX와 기타 TXT를 각각 첨부하고 목록·원자료 보고서 대조 제출용 브라우저 검증 기록 참조
불완전한 자료와 입력 오류를 확인할 수 있다 고용자료를 뺀 샘플, 다른 회사 자료 차단·신고서 연도 불일치 회귀검증 검토 보조 범위에서 구현; 부족자료 판정의 세무적 완전성 미검증
현재 자료로 보고서 생성·저장이 가능하다 보고서 1~4 열기와 HTML 다운로드·Reset 확인 제출용 브라우저 검증 기록 참조

계정 진입 검증: 프로덕션에서 가입·실제10초 후 자동 로그인·재로그인·로그아웃 통과. 안내 팝업은 가상 시계로120~180초 조건 확인.

구현 범위와 제외할 일

HTML/CSS/JavaScript 앱이며 선택한 회사 파일은 브라우저에서 처리한다. 웹 회원인증은 Cloudflare Pages Functions·D1을 사용하며 솔트와 비밀번호 해시, 만료 세션으로 처리한다. 원 신고서 PDF를 요약 XLSX보다 우선한다. 자동계산 대상은 인식 가능한 서식의 12월 결산 2021~2025년이다. Windows EXE의 기관 수집 연결은 웹 제출 시연과 별개다.

이번 제출에서 하지 않는 일은 ① 확정 환급액·모든 공제 조합의 정확성 보증 ② 국세청 경정청구 자동 제출 ③ 노무사 업무·고용지원금 신청 ④ 회사 원자료 클라우드 보관·비밀번호 재설정·이메일 인증 ⑤ 스캔 PDF OCR과 모든 기관 서식 지원이다.

품질·개인정보·후속 과제

실제 회사 원본·식별정보·생성 보고서는 공개 저장소에 넣지 않는다. 샘플은 완전한 가상자료다. 새로고침 시 회사 입력은 초기화되고 인증 쿠키는 유지되며 로그아웃으로 종료한다. 계정 DB에는 회사 첨부를 저장하지 않는다. 소계 명칭과 연노랑 표시를 일관되게 제공한다. 세액 최적화·기신고 공제 대체·농특세·자료 충분성 판정은 전문가 사례로 추가 검증한다. 계정·배포 검증과 영상 제출 여부는 검증 기록에서 관리한다.

처음에는 경정청구 자료 수집부터 계산·보고서까지 연결하려 했다. 작업 중 세무사 업무로 범위를 좁히고 노무사 관련 신청 기능을 제외했다. 이번 제출에서는 자료 업로드, 기관·서류·연도 분류, 검토 결과 확인, 보고서 생성으로 이어지는 흐름에 집중했다. 기타 자료도 이름과 부서·연도를 적어 한 파일씩 첨부할 수 있게 했다. 후속 요청으로 ID/PW 로그인, 회원가입, 2~3분 후 가입 안내와 가입10초 후 자동 로그인도 추가했다.

어려웠던 점과 해결 과정

같은 원자료로 만든 전문가 결과와 앱 결과가 달랐다. 이를 통해 화면이 완성되고 테스트가 통과해도 세법상 계산이 정확하다는 뜻은 아니라는 점을 확인했다. 공제 최적화와 기신고 공제 대체 등의 한계를 문서화하고, 확정 환급 서비스라는 표현 대신 검토 보조 도구로 범위를 정했다. 해당 금액의 정답을 이번 제출에서 확정한 것은 아니다.

또한 공개 저장소에 실제 회사자료가 섞일 위험이 있었다. 원자료를 저장소 밖에 백업한 뒤 공개 소스에서 분리하고 Git 이력을 정리했다. 기본 회사 데이터를 제거하고 빈 상태에서 시작하도록 바꿨으며, 공개 파일·이력 점검 도구와 독립적인 가상 샘플을 마련했다. 실제 자료를 단순히 이름만 바꾼 샘플은 사용하지 않았다. 회원기능을 추가할 때에는 계정 인증정보와 회사자료를 분리하고, 자료 Reset과 로그인 세션 종료를 구분했다.

사용자가 자료를 한꺼번에 올리는 방식만으로는 어떤 서류를 어디에 넣어야 하는지 알기 어려웠다. 기관·서류·연도별 18칸을 제공하고, 인식되지 않는 기타 첨부는 자동계산에 반영하지 않는다고 표시했다. 첨부 성공과 요건 충족을 구분하는 것이 중요했다.

AI 협업에서 배운 점

‘업로드를 개선해 줘’보다 ‘기관·서류명·연도별로 한 파일씩 넣고, 기타는 이름을 적어 첨부하게 해 줘’처럼 행동과 예외를 지정한 요청이 구현·검증으로 연결하기 쉬웠다. AI는 화면 수정과 테스트 작성에 도움이 됐지만, 개인정보 삭제 범위와 세무적 결론은 결과물을 따로 확인해야 했다. AI 답변을 근거 없이 최종 판단으로 쓰지 않는 것이 핵심이었다.

남은 일과 다음 시도

Cloudflare 배포 주소를 생성하고 실제 HTTPS 환경에서도 가상 샘플과 보고서 저장을 검증했다. 개인정보 점검 후 공개 GitHub 저장소도 만들었다. 3분 이내 영상은 아직 제작해야 한다. 다음 개발은 전문가가 검토한 가상 기준 사례로 공제 조합·농특세·이월·추징을 대조하고, 부족자료 목록에 ‘왜 필요한가’를 연결하는 것이다. 범위를 넓히기보다 한 사례의 입력부터 근거까지 재현 가능하게 만드는 것을 우선한다.
